# Evidence Run 002 — Live External Producer

**Status:** Complete / PASS / Frozen
**Scope:** Downstream experiment only
**Continuity Core changes:** None
**Elapsed semantics:** Controlled explicit fixture only

## Purpose

Run 002 adds one narrow piece of evidence beyond the verified offline baseline: a real nondeterministic external producer can be serialized to bytes, preserved, evaluated through the unchanged Path A boundary, and replayed with the exact same bytes and controlled elapsed input.

This run does **not** add agent semantics, provider semantics, authorization semantics, or real-world timing semantics. The producer remains outside Arcstone authority.

## What was added to the lab

- `src/live-producer-run.mjs` — exact-byte preservation, evaluation, replay, and evidence finalization.
- `src/run-live-producer.mjs` — command-line entry point.
- `test/live-producer-run.test.mjs` — tests byte preservation, replay identity, local hash chaining, and run-directory immutability.
- `npm run evidence:live-producer` — builds the existing Rust bridge and executes the live-producer evidence runner.

No file under `reference/arcstone-continuity-core/` is changed by this addition.

## Step 1 — Verify the repository first

From the repository root in PowerShell:

```powershell
npm.cmd run verify
```

Do not continue if the existing verification chain is not green.

## Step 2 — Obtain one real nondeterministic producer output

Use one live LLM, agent, local model, API, or other nondeterministic producer **outside this repository**.

Save the producer output to a file. For example:

```text
C:\path\to\run-002-producer-output.txt
```

The file is the serialization boundary for this experiment. The bytes in that file are what Run 002 preserves and evaluates. The experiment does not claim that the file is an Arcstone frame or canonical object.

For a first run, keep the output comfortably below 4096 bytes so the experiment is primarily about external-producer provenance and exact replay rather than the size fault boundary.

## Step 3 — Execute Run 002

Use a controlled explicit elapsed value. `5000` microseconds is the recommended first fixture because it is already inside the verified offline matrix and is **not** a measurement of model or network latency.

Example:

```powershell
npm.cmd run evidence:live-producer -- --input="C:\path\to\run-002-producer-output.txt" --producer="live-llm-manual-export" --elapsed-us=5000 --run-id=run-002
```

The runner will:

1. refuse to overwrite an existing `evidence/run-002/` directory;
2. read the source file as raw bytes;
3. preserve those bytes as `producer-output.bin` **before** Path A evaluation;
4. verify the preserved byte count and SHA-256 against the source bytes;
5. evaluate the preserved bytes through the existing Rust bridge with the controlled elapsed value;
6. re-read the preserved evidence payload;
7. evaluate the exact preserved bytes again with the same controlled elapsed value;
8. compare explicit inputs and Path A results;
9. create a hash-chained observation record and SHA-256 manifest;
10. finalize the evidence directory only when the run machinery completes.

## Expected evidence directory

A successful run creates:

```text
evidence/run-002/
├── environment.txt
├── observations.jsonl
├── producer-output.bin
├── SHA256SUMS.txt
└── summary.json
```

`summary.json` should report:

```json
{
  "experimentStatus": "PASS",
  "identicalExplicitInputs": true,
  "identicalResults": true
}
```

The Path A state itself may be `PASS`, `LEDGER_CORRUPTION`, or another state permitted by the unchanged predicate for the supplied explicit inputs. `experimentStatus: PASS` means the capture/replay experiment succeeded; it does **not** mean that Path A returned `PASS` and it is not an authorization decision.

## Step 4 — Do not rewrite Run 002

After a successful run, treat `evidence/run-002/` as immutable evidence. Do not edit the payload, JSONL, summary, environment record, or checksum manifest.

If another producer or another condition is tested later, use a new run ID such as `run-003`.

## Bounded claim if Run 002 passes

A successful Run 002 supports this narrow statement:

> A serialized output from a live nondeterministic external producer can be preserved as raw bytes, evaluated through the unchanged Path A boundary with a controlled explicit elapsed input, and replayed with identical explicit inputs and an identical Path A result.

It does **not** establish model alignment, AI safety, production authorization, real-world latency correspondence, complete membrane behavior, or framework-wide interoperability.

## Stop conditions

Stop rather than expanding the architecture if Run 002 appears to require any of the following:

- changing Continuity Core source, constants, lattice, or status mappings;
- mapping LLM inference time, API latency, network duration, or scheduler jitter into `elapsed`;
- calling the producer output an Arcstone frame or certificate;
- importing provider-specific semantics into Path A;
- adding an agent framework, MCP server, actuator, or authorization system merely to make this experiment pass.

**Evidence before expansion. Preserve the core. Test the boundary.**
