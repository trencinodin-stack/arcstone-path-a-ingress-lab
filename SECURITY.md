# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability or execution-boundary issue in `arcstone-path-a-ingress-lab`, please do not open a public issue.

You can submit reports through either of the following private channels:

1. **GitHub Private Vulnerability Reporting (Recommended):**
   * Go to the **Security** tab of this repository.
   * Click **Report a vulnerability**.
   * Fill out the form to submit a private report directly to maintainers.

2. **Email:**
   * Contact us at **`security@arcstoneos.com`**.

### What to Include

* Description of the producer-input, serialization, replay, evidence-integrity, or boundary-bypass issue.
* Minimal reproduction steps or proof-of-concept.
* The affected version or commit, if known.

### Experimental Scope

`arcstone-path-a-ingress-lab` is an experimental, downstream, non-canonical reference implementation for producer-independent invocation and evidence capture against the Arcstone Continuity Core Path A predicate.

Its security claims are limited to the explicitly tested experimental conditions and preserved evidence.

It does not claim production-grade security, arbitrary-code containment, remote-attacker resistance, universal sandbox or kernel security, model alignment, or general AI safety.

We will acknowledge receipt within 48 hours and work with you on an appropriate resolution timeline.
